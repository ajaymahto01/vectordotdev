# Vector Nginx Logging POC

This project demonstrates a proof of concept (POC) for shipping logs from an Nginx server to Elasticsearch using Vector.dev, and visualizing the logs with Kibana. The setup is entirely containerized using Docker, allowing for easy deployment and management.

## Project Structure

The project consists of the following files and directories:

- **docker-compose.yml**: Defines the services for the Docker containers, including Nginx, Vector.dev, Elasticsearch, and Kibana. It specifies how the containers interact and the volumes for persistent data.
  
- **.env**: Contains environment variables used in the Docker Compose setup, such as configuration settings for Elasticsearch and Kibana.

- **Makefile**: Includes commands for building and managing the Docker containers, such as starting, stopping, and cleaning up the environment.

- **nginx/**: Contains the configuration and Dockerfile for the Nginx server.
  - **Dockerfile**: Defines the Docker image for the Nginx server.
  - **nginx.conf**: Main configuration for the Nginx server.
  - **conf.d/default.conf**: Default server configuration for Nginx, including access log settings.

- **vector/**: Contains the configuration for Vector.dev.
  - **vector.toml**: Configuration file for Vector.dev, defining sources, transforms, and sinks for the log shipping pipeline.
  - **certs/**: Directory for optional TLS files if secure communication is needed between services.

- **elasticsearch/**: Contains the configuration for the Elasticsearch service.
  - **elasticsearch.yml**: Configuration file for Elasticsearch, including cluster settings.

- **kibana/**: Contains the configuration for the Kibana service.
  - **kibana.yml**: Configuration file for Kibana, including settings for the Elasticsearch URL.

- **volumes/es-data/**: Directory used to persist Elasticsearch data, ensuring that data is not lost when the container is stopped or removed.

- **logs/nginx/access.log**: Log file generated by Nginx, which will be monitored and shipped to Elasticsearch by Vector.dev.

## Setup Instructions

1. **Clone the Repository**: Clone this repository to your local machine.

2. **Build and Start the Services**: Run the following command to build and start all services:
   ```
   make up
   ```

3. **Access the Services**:
   - Nginx: [http://localhost:80](http://localhost:80)
   - Kibana: [http://localhost:5601](http://localhost:5601)

4. **View Logs**: Access the Nginx logs at `logs/nginx/access.log`. These logs will be shipped to Elasticsearch and can be visualized in Kibana.

## Quick start (recommended)

From the `vector-nginx-logging-poc` directory run:

```bash
# build and start the stack
docker compose up --build -d

# check service status
docker compose ps
```

Generate traffic against nginx to produce log lines:

```bash
# from the host
curl http://localhost/
curl http://localhost/nonexistent
```

Open Kibana at http://localhost:5601 and create an index pattern matching `nginx-logs-*` (time field: `@timestamp` if present). Then go to Discover to see logs arriving.

## Verification commands

- Vector logs: `docker compose logs -f vector`
- Elasticsearch health: `curl http://localhost:9200/_cluster/health?pretty`
- Search recent nginx docs in Elasticsearch:

```bash
curl -s 'http://localhost:9200/nginx-logs-*/_search?pretty' -H 'Content-Type: application/json' -d'{"size":5,"sort":[{"@timestamp":{"order":"desc"}}]}'
```

## Troubleshooting

- If no logs appear in Kibana, check that Vector can read the mounted log files and that file paths match (`/var/log/nginx` inside the containers).
- Check file permissions on `logs/nginx` and ensure the logs are being written by the nginx container.

## Usage

- Modify the Nginx configuration in `nginx/nginx.conf` and `nginx/conf.d/default.conf` as needed to customize logging behavior.
- Update the Vector configuration in `vector/vector.toml` to adjust log shipping settings.
- Use the `.env` file to configure environment variables for Elasticsearch and Kibana.

## Notes

- Ensure Docker and Docker Compose are installed on your machine.
- This setup is intended for development and testing purposes. For production use, consider additional security and performance optimizations.
